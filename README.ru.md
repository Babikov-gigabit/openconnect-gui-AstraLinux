# OpenConnect GUI — сборка для Astra Linux

*English version: [README.md](README.md)*

Этот репозиторий — форк официального проекта
[OpenConnect GUI](https://gitlab.com/openconnect/openconnect-gui), доработанный
так, чтобы он собирался и упаковывался в нативный `.deb` на **Astra Linux 1.8**
(основана на Debian 12 «bookworm»). Код самого приложения не менялся — правки
касаются только Debian-пакетирования (`debian/`), необходимого для успешной
сборки на Astra Linux.

## Что было исправлено и почему

Оригинальная упаковка `debian/` без изменений падала на этапе конфигурации
`cmake` с ошибкой:

```
Could not find a package configuration file provided by "Qt6" ...
```

При этом `qt6-base-dev` был установлен, а сам файл `Qt6Config.cmake`
физически лежал по пути
`/usr/lib/x86_64-linux-gnu/cmake/Qt6/Qt6Config.cmake`. Причина — используемая
версия `cmake` на этой системе не определяет `CMAKE_LIBRARY_ARCHITECTURE`
автоматически, из-за чего не ищет пакеты в multiarch-каталоге
(`x86_64-linux-gnu`) самостоятельно.

**Исправление:** в `debian/rules` добавлена явная передача
`-DCMAKE_PREFIX_PATH=/usr/lib/x86_64-linux-gnu/cmake` в `cmake` — это
позволяет найти `Qt6Config.cmake`, а вместе с ним и `OpenGL`/`GnuTLS`, и
остальные зависимости, определяемые через CMake config-режим.

Больше никакие файлы не менялись. Итоговый бинарник — это неизменный
upstream OpenConnect GUI версии 1.6.2.

### О замкнутой программной среде Astra Linux

В Astra Linux 1.8 работают модули ядра `digsig_verif`/`parsec` (механизм
«Замкнутая программная среда»). При этой политике обычный пользователь не
может выполнить `chmod +x` на только что созданном файле — а именно это
делает `dpkg-buildpackage` (например, при установке исполняемого бита на
`debian/rules`, а также на этапе `dh_fixperms`). **Сборку нужно выполнять от
root** (например, через `sudo`). Сама компиляция и линковка этим ограничением
не затрагиваются — блокируется только смена прав на только что созданных
файлах для непривилегированного пользователя.

Если рабочая копия репозитория лежит на общей папке VirtualBox (`vboxsf`),
учтите: такие точки монтирования обычно показывают у всех файлов один и тот
же фиксированный режим доступа (например, `0770`), из-за чего `git`/`cp`
неверно определяют, какие файлы «исполняемые». Инструкция по сборке ниже
предполагает копирование дерева исходников на обычную файловую систему перед
сборкой — именно чтобы избежать этой проблемы.

## Сборка пакета

Установите зависимости для сборки (доступны из репозиториев `main` и
`extended` Astra Linux после свежего `apt-get update`):

```bash
sudo apt-get update
sudo apt-get install -y devscripts build-essential debhelper cmake pkg-config \
    qt6-base-dev qt6-base-dev-tools qt6-scxml-dev \
    libgnutls28-dev libopenconnect-dev libspdlog-dev libxml2-dev
```

Сборка (от root — причина объяснена выше; запускайте из обычной файловой
системы, не с `vboxsf`/сетевой шары):

```bash
sudo dpkg-buildpackage -us -uc -b
```

В результате в родительском каталоге появится
`openconnect-gui_<версия>_amd64.deb` (и отдельный `-dbgsym` пакет с отладочной
информацией).

## Установка

```bash
sudo apt install ./openconnect-gui_1.6.2-1_amd64.deb
```
(ВАЖНО если вы ставите через графику то могут быть проблемы с зависимостями рекомендую установить через терминал)
`apt` сам подтянет `openconnect`, `vpnc-scripts` и рантайм-библиотеки
Qt6/GnuTLS/spdlog прямо из репозиториев Astra Linux — вручную ничего
разруливать не нужно, если список пакетов недавно обновлялся
(`apt-get update`).

Для машин без доступа к репозиториям Astra смотрите
[Releases](../../releases) — там лежит offline-архив с этим `.deb`, всеми его
зависимостями в виде `.deb`-файлов и скриптом `install.sh`.
